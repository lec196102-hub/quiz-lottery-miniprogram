# 答题抽奖小程序（可交互原型 + PRD）

答题通关才能抽奖的微信小程序演示项目：参与者扫码登记姓名 + 工号，从 150 题单选题库随机抽 5 题，答对 3 题通关获得 1 次抽奖机会；奖品分 3 个等级（一/二/三等奖共 155 份），**恒定 25% 中奖率**，抽中的奖品从奖池实时扣减，某等级抽完自动剔除（后续不再抽到该等级但中奖率不变），每人仅可抽奖一次。

> 状态：低保真可交互原型 + 需求文档（PRD），非生产代码。抽奖核心算法已用脚本验证（见下）。

## 对应 PRD 的 8 条需求

| # | 需求 | 原型覆盖 |
|---|------|----------|
| 1 | 扫码 / 链接参与 | 首页「立即参与」，携带 activityId 进入 |
| 2 | 登记姓名 + 工号 | 身份登记页，行内校验 + 同工号不同姓名告警 |
| 3 | 批量导入 150 道单选题 | 后台题库管理 · 批量导入（含 CSV 校验与错误行反馈） |
| 4 | 每次随机 5 题，答对 3 题通关 | 答题页（进度条 / 解析），服务端判分 |
| 5 | 中奖提示等级 / 未中提示谢谢参与 | 抽奖结果页四态（一/二/三/谢谢参与） |
| 6 | 三等级奖池 155 份，恒定 25%，抽完剔除 | 抽奖引擎：两阶段判定 + 剩余库存加权选级 + 原子扣减 |
| 7 | 通关可多次答题，抽奖仅一次 | 唯一索引防重复；再答一次 / 每人仅可抽一次 |
| 8 | 后台查看获奖名单与时间 | 获奖名单页（筛选 / 导出 CSV） |

## 本地运行

方式一（推荐，零依赖）：直接用浏览器打开 `prototype/index.single.html`。

方式二（分离版，需 HTTP 加载 ES Module）：

```bash
cd prototype
node server.cjs          # 启动后访问 http://127.0.0.1:8173
```

## 抽奖算法要点（风险最高、必须做对的部分）

1. **阶段一 · 中奖判定**：以恒定 `winRate=0.25` 判定「中不中」，不随奖池变动。
2. **阶段二 · 加权选级**：在 `remain>0` 的奖项中按剩余库存加权选等级（一等奖自然稀缺）。
3. **阶段三 · 原子扣减**：`UPDATE ... SET remain=remain-1 WHERE level=? AND remain>0`，扣减失败则剔除该等级重试（最多 3 次）后降级为「谢谢参与」。
4. **防超发 / 防重复**：库存条件更新 + 中奖记录唯一索引 `(activityId, empNo)`。

> ⚠️ 关键测算：25% × 155 份 ≈ **需 620 人次抽奖**才能送完全部奖品。若参与人数不足，活动结束会剩大量奖品——上线前需与业务确认预期人数与中奖率。
